## 3. Python 主入口严格比较和失败契约

源码入口：[runDelivery.py](../runDelivery.py)、[runLogged.ps1](../runLogged.ps1)。

1. `verifyFrozenBaseline`先检查历史manifest PASS与真实returncode=0，再遍历记录中的输入和产物哈希。本次audit报告实际包含107条匹配记录，没有只比较存在性。
2. `compareArrays`使用`allow_pickle=False`，字段集合、数组形状和全部值均需相等，NaN位置一致；没有用均值、前几行或宽容差替代全部数组比较。NaN相等是为合法Q4域外表示准备，物性与输入有限值另行检查。
3. final对Q1/Q23/Q4各样本NPZ和连续事件精确比较，Q23/Q4的完整`completion`字典精确比较，能覆盖严格报告和阈值结果。N40 audit不借用final字段谎报相同网格。
4. final导出后要求导出器`status=PASS`和`fully_verified_with_live_Run`。导出器对全部工作簿/未舍入归档回读，独立查询live Run工作簿样本、全部正文CSV单元；主入口再逐字节比较全部解压CSV直至双方EOF，因此不能只靠gzip封装元数据不同判失败，也不会忽略文件尾部多行。
5. 主入口还逐字节比较所有生成的正文CSV。此处glob自身不负责“必需表数量”的合同，完整必需表集合由`validatePaperTables`明确核对，已检查调用顺序先经过该验证，所以未发现静默零表PASS路径。
6. 所选profile的求解、比较或输入起止哈希变化抛错，内层结果写FAIL并重新抛出，外部进程应非零退出。局部已完成文件保留，最终artifactManifest带本次状态，不把部分结果自动晋升为成功。
7. 子程序自身`actualProcessExitCode=null`正确保留；父进程另记真实`actualExitCode`。如果最终写清单期间发生I/O异常而子程序状态文件已写PASS，仍需结合外部非零退出判失败，不能单看一个PASS字段；当前审查没有观察到这种失败。
8. 源码、输入、模板在启动及结束复核；直接根Python文件参与清单，MATLAB和监督脚本属于另有记录的执行链。根Python未修改的当前运行有固定哈希证据。`runLegacyAudit`把原生产模块目录放到sys.path首位时使用不同模块名，原版与驼峰副本不会因同名import互相替代。
9. 外部监督每秒观察目标进程工作集、记录起止主入口SHA256并返回真实退出码；没有GUI完成自动标记。观察内存只覆盖抽样时点及目标进程，源码已说明排除瞬态峰值与其他进程。

现有“PASS”边界是所选profile的真实运行与验证。`autoresearch.json`中的`heldOutCheck`是final预定对照描述，其文字不构成final已实际完成的证据；final必须有自己独立的runResult、完整导出回读与父进程退出记录。
