## 必须修复的提交工程问题

1. **统一包根目录及文件布局。** ZIP 为 `code/`、`figures/`、`evidence/`，Python 仍用 `parents[3]`，MATLAB 仍向上固定四层，读写 `paper_output/...`。14 个交叉验证脚本还直接写死作者 D 盘绝对目录。需要所有拟供复现入口统一定位解压根目录、输入和输出。
2. **提供不依赖历史工作区的生产入口。** `final`、`audit` 都无条件核验冻结账本的 107 项历史文件。即便按 SHA256 对包内重定位文件进行对应，仍有 48 项内容不在 ZIP 中；仅改变文件夹名称不能补齐。应让独立求解、导出、回读可以只依赖包内输入执行，将完整历史逐字节回归保留为明确的可选检验，不能跳过后仍标记其 PASS。
3. **补齐并正确定位必需输入。** 两份清洗 CSV 存在于 `figures/`，而模型从 `paper_output/data_cleaned/` 读取。四份原始输出模板未打包，导出器仍明确读取模板；ZIP 根部的四份最终结果不能冒称原模板。若交付包含从原始数据开始的完整流程，也需纳入附件1/2及其必要输入清单。
4. **使依赖声明覆盖拟运行的代码。** 三项 requirements 足以安装核心求解依赖，随包的五个数据/绘图/验证脚本还需要 `matplotlib`，两个历史审计脚本需要 `pymupdf`；新环境已确认未安装这两个包。`publication_plots.py` 还强制依赖 `C:/Windows/Fonts/msyh.ttc`。需要完整依赖说明、字体选择机制及各入口用途说明。
5. **重写实际可执行的启动说明。** README 使用作者工作区和 Python 安装路径，要求打开 ZIP 内不存在的 `.sln/.pyproj`，六个本地 Markdown 链接均失效。监督器默认 `C:\Python314\python.exe`，UTF-8 无 BOM 与 `Kill(bool)` 也影响 PS5.1。需提供解压根目录下的真实命令、版本要求、输出说明及错误判定。
6. **建立迁移数值验收标准。** 当前入口要求事件、数组和原精度 CSV 与冻结结果逐位完全一致；它适合原环境重命名回归。异机验收应预先规定采样、单位、误差容限，并重查未舍入阈值、守恒和表格全量回读；逐位一致可保留为附加指标。不能用调整容差掩盖严格达标条件或四位舍入边界。

正式运行还应说明 64 位解释器、RAM 与临时磁盘需求。已有运行文档记录 Q4 密集输出缓存约 8.33 GB；本机约32 GB内存是已使用环境，不是已测定的最低内存。纯 Python CLI 主求解不应把 MATLAB、Visual Studio 或 GPU 作为算法必需依赖。MATLAB 在本项目承担独立交叉核验，VS GUI 是团队另行要求的可视化复现环节。
