## 核对结论

附件明确提供 MATLAB 原生 `webwrite` 示例，最小通信链只需要四个 POST 接口。登录完成并开启演练、倒计时结束后，才能验证接口是否可用。接口未开放期间的连接失败不说明程序损坏。

`robot_id` 必须是当前登录参赛队号；通信协议没有 `team_id` 字段。如程序以 `team_id` 为本地变量名，必须仅作为运行时参数传入并映射为 `robot_id`，不得把队号写入代码、公开日志或请求的额外字段。实际队号不应由读取模拟器内部身份文件取得。

## 请求与响应

默认地址为 `http://127.0.0.1:2026`，实际以模拟器设置为准。只监听本机回环地址。

| 接口 | 必填请求字段 | `accepted=true` 时的专属响应 |
|---|---|---|
| `POST /enter` | `arena_id`, `robot_id`, `request_id` | `max_virtual_duration_s`, `max_real_duration_s`, `remaining_real_duration_s` |
| `POST /measure` | 公共三字段及 `position: {x,y}`, `channel` | `measure_result`；只有值为 `direction` 时才有 `svd_deg` |
| `POST /clear` | 公共三字段及 `position: {x,y}`, `channel` | `clear_result` |
| `POST /exit` | `arena_id`, `robot_id`, `request_id` | `exit_reason`，成功主动退出固定为 `user_exit` |

公共请求约束：

- `arena_id` 为 ASCII 字符串 `default`。
- `robot_id` 逐字节等于当前登录参赛队号，UTF-8 长度 1—64 字节。
- `request_id` 为当前测试会话内幂等键，UTF-8 长度 1—128 字节。两个标识均不可含控制字符或不可见格式字符。
- `position.x`、`position.y` 是有限 JSON number，各分量绝对值不超过 2,000,000 米；可以在目标区域以外。
- `channel` 是 1—20 整数；数值恰为整数的 `1.0` 可接受，`1.5` 不可接受。
- `Content-Type` 必须为 `application/json`，可带且只可带 `charset=utf-8` 参数。`Content-Encoding` 省略或为 `identity`。
- 请求体为无 BOM 的 UTF-8 JSON 对象，无重复键，嵌套不超过 16 层，总体不超过 65,536 字节。
- 路径精确匹配，不接受尾随斜线或查询参数。未知 JSON 字段会被拒绝，不能额外发 `team_id`、模式或调试字段。

所有 JSON 业务响应都包含 `accepted`、`real_timestamp_ms` 和 `virtual_time_s`。拒绝时仅有这三字段，且 `virtual_time_s=0` 不是当前真实虚拟时刻，程序应保留最近一次已接受动作的虚拟时间。虚拟时间为可带小数的 number，最多保留 6 位小数。

检测响应字符串为 `no_signal`、`near`、`direction`。`no_signal` 不证明该频道无目标；`near` 表示在信号有效覆盖范围内且距离不超过 5 米，此时不返回示向度；`direction` 的 `svd_deg` 是带误差的度数。

清除响应为 `success` 或 `no_target_in_range`。距离不超过 20 米即能清除指定频道目标，定向朝向不影响清除。`/clear` 不修改测向机当前频道，也不收取频道切换时间。

## 最小演练序列

以下为附件 2 第 10 节的计时示例，可覆盖进入、位置移动、频道切换、清除和主动退出，不依赖案例真值。该序列仅检查接口，不是搜索清除算法。

| 次序 | 请求 | 位置 | 频道 | 接受后的虚拟时间 s |
|---|---|---|---|---|
| 1 | `/enter` | 无 | 无 | 0 |
| 2 | `/measure` | (300,400) | 1 | 105 |
| 3 | `/measure` | (300,400) | 2 | 111 |
| 4 | `/clear` | (300,0) | 3 | 未发现为 194；成功为 196 |
| 5 | `/measure` | (300,0) | 2 | 分别为 199 或 201 |
| 6 | `/exit` | 无 | 无 | 与上一步相同；`exit_reason=user_exit` |

第 2 步移动 500 米，耗时 100 秒，加检测 5 秒；第 3 步换频道加 1 秒、检测加 5 秒；第 4 步移动 400 米加 80 秒、光学精确定位与清除合计 3 或 5 秒；第 5 步测向机仍为频道 2，仅加检测 5 秒。

每步必须同时确认正常 HTTP 响应和 `accepted=true`。每个新动作使用新 `request_id`，完整等待当前响应后才能发下一步。正常合法串行动作没有速率上限，检测的 5 秒是虚拟耗时，现实中无需等待 5 秒。

网络超时或连接中断时，重试同一动作必须原样复用路径、请求内容和 `request_id`；不得因为重试而换新 ID。同 ID 同内容返回首次响应且不会重复执行；同 ID 改路径、位置或频道等会返回 409。最小测试无需主动制造故障或无效高频流量。

## MATLAB 原生最小方法

附件 2 第 11 节直接使用以下原生方法；无需引入 Python 或其他进程。

```matlab
% robotId 来自运行时参数，不在源代码中写真实参赛队号。
baseUrl = 'http://127.0.0.1:2026';
options = weboptions('MediaType', 'application/json', 'Timeout', 5);
payload = struct('arena_id', 'default', ...
    'robot_id', char(robotId), 'request_id', 'enter-1');
response = webwrite([baseUrl '/enter'], payload, options);
assert(isfield(response,'accepted') && response.accepted == true, ...
    'Simulator did not accept enter');
remainingTime = response.remaining_real_duration_s;
```

动作请求在公共结构上增加：

```matlab
payload.position = struct('x', 300, 'y', 400);
payload.channel = 1;
```

每个请求应独立构造，尤其 `/exit` 只保留三个公共字段，不能误带前一次的 `position` 或 `channel`。附件示例中的 `webwrite` 便于可用性检查；完整参赛客户端还需捕捉连接/HTTP 异常、保存请求与响应，并制定符合原 ID 规则的重试逻辑。不能把 MATLAB 函数返回且未检查 `accepted` 视为动作已执行。

以上代码只供主代理在 MATLAB GUI 中组成测试，不是已运行证据或正式建模源码。采用结果前仍需团队人工核实。

## 窗口与退出

开启演练并确认后，模拟器准备数据，再显示 5 秒倒计时。倒计时结束才开放接口并启动 25 分钟测试窗口；`/enter` 成功起还有最长 20 分钟程序运行时间，实际截止取两者较早。应使用 `/enter` 返回的 `remaining_real_duration_s`，不能固定假设还有 1,200 秒。虚拟世界上限为 360,000 秒。
